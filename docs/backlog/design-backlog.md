# Business English Daily Quiz — Design Backlog

> 이 문서는 현재 제품/콘텐츠 Work 범위 밖의 후속 디자인 아이디어를 보관하는 backlog다.
> 아직 확정된 UI spec이 아니며, 캐릭터·브랜드·비주얼 시스템 설계 단계에서 검토한다.

## 1. Visual Scenario Support

각 문제에 상황을 빠르게 이해시키는 **간단한 visual 요소**를 넣는 방향을 검토한다.

예:

- 이메일 작성 중인 인물
- 화상회의 중인 팀
- 전화를 받는 직원
- 메신저 대화 상황
- 고객과 대면 회의 중인 장면

목적은 장식이 아니라:

1. 문제 상황을 읽기 전에 대략적인 context를 빠르게 파악하게 함
2. 텍스트 밀도를 낮춤
3. 직장생활 시뮬레이션 느낌을 강화함
4. 반복 등장 인물에 친밀감을 형성하게 함

---

## 2. Repeating Characters

내부적으로 소수의 반복 등장 인물을 설정하는 방향을 검토한다.

예시:

- 김대리
- 최과장
- 이사원
- 해외 고객 담당자
- vendor 담당자
- 외국인 동료

캐릭터는 문제의 학습 목적을 방해하지 않도록 과도한 서사나 설정을 넣지 않는다.

각 캐릭터는 다음 정도의 일관성만 가질 수 있다.

- 역할 / 직급
- 팀 또는 기능
- 대략적인 업무 관계
- 커뮤니케이션 스타일
- 반복적으로 마주치는 업무 상황

---

## 3. Character Continuity

문제마다 전혀 다른 회사·업종·인물이 등장하지 않도록 한다.

사용자가 반복해서 문제를 풀면서 느슨한 연속성을 느낄 수 있게 한다.

예:

- 어제 고객 자료를 요청했던 김대리가 오늘 회의에서 같은 프로젝트를 논의
- 최과장이 우선순위를 정하거나 리스크를 확인
- 이사원이 내부 협업 또는 handoff에 등장

단, 전날 문제를 기억해야만 다음 문제를 풀 수 있어서는 안 된다.

---

## 4. Company Worldbuilding

가상의 회사는 너무 구체적인 산업에 고정하지 않는다.

후보 방향:

> 해외 고객·파트너·vendor와 프로젝트를 수행하는 한국 기반의 중견 B2B 회사

이 설정은 다음 상황을 자연스럽게 허용한다.

- 고객 커뮤니케이션
- vendor 관리
- 내부 협업
- 프로젝트 일정
- scope 조정
- 보고 및 승인
- 품질 이슈
- 글로벌 미팅

회사 이름은 필수 아님.

브랜드/캐릭터가 충분히 정리된 뒤 필요 여부를 결정한다.

---

## 5. Illustration Style Principles

향후 시각 스타일은 다음을 고려한다.

- 단순하고 빠르게 이해 가능
- Toss 미니앱 환경과 충돌하지 않는 가벼운 UI
- 다른 외국어 학습 앱의 시각 정체성을 직접 연상시키지 않음
- 과도한 gamification 피하기
- 캐릭터가 너무 유아적이거나 만화적이지 않도록 조절
- 직장인 타겟에게 가볍지만 유치하지 않은 톤 유지
- 텍스트보다 visual이 더 많은 주의를 빼앗지 않도록 함

---

## 6. Visual Density

모든 문제에 복잡한 일러스트를 넣을 필요는 없다.

가능한 방향:

- 작은 캐릭터 vignette
- channel icon + 캐릭터
- 회의/전화/메일을 나타내는 한 장면
- 상황별 반복 가능한 배경 세트

미니앱의 핵심인 **2~3분 내 완료**를 방해하지 않아야 한다.

---

## 7. Stage별 Visual Language

Stage마다 subtle한 visual 차이를 둘 수 있다.

예:

### Inbox
- 이메일/메신저
- 책상
- 문서
- 알림

### Speak Up
- 회의실
- 화상회의
- 발언
- 질문/응답

### Handle It
- 전화
- 고객 미팅
- 문제 알림
- 긴장된 대화

단, 색상이나 효과를 지나치게 다르게 써서 별개의 서비스처럼 보이게 해서는 안 된다.

---

## 8. Result Screen Theme

현재 방향:

- 직장생활 survival / 퇴근 theme
- 점수에 따른 가벼운 결과 메시지
- 실패감을 과도하게 주지 않음

예시 방향:

- 3/3: 회사의 에이스!
- 2/3: 무사 퇴근
- 1/3: 아슬아슬한 퇴근
- 0/3: 가벼운 야근/복습 개그

정확한 문구는 별도 copy 작업에서 확정한다.

---

## 9. Review Visual Design

복습 기능은 학습 효과를 높이되 앱을 무겁게 보이게 하지 않는다.

복습 카드:

- compact scenario 1~2문장
- 선택지 없음
- `[정답 보기]`
- reusable pattern
- `[다음에 다시 보기]`
- `[이제 알겠어요]`

복습이 flashcard/SRS 관리 도구처럼 보이지 않도록 한다.

---

## 10. Saved Expression UX

`내 표현에 저장`은 단순 bookmark가 아니라:

> 이 표현을 내 것으로 만들기

기능이다.

향후 UI copy 후보:

- 내 표현에 저장
- 내 표현으로 저장
- 다시 연습하기

정확한 label은 사용자 테스트 후 결정한다.

---

## 11. Visual Asset Reuse

문제 100개 이상을 운영할 경우 문제마다 완전히 새로운 이미지를 제작하는 것은 비효율적일 수 있다.

따라서 다음 재사용 구조를 검토한다.

- 캐릭터 pose library
- 이메일 장면
- 회의 장면
- 전화 장면
- 메신저 장면
- 고객/내부/외부 partner 조합

같은 asset을 상황에 따라 재조합할 수 있도록 한다.

## 13. Current Design Principle

비주얼 요소를 추가하더라도 최우선 원칙은 다음과 같다.

> **사용자가 상황을 더 빨리 이해하고, 더 쉽게 다시 돌아오게 만들어야 한다.**

비주얼 때문에:

- 문제를 읽는 데 더 오래 걸리거나
- 화면이 복잡해지거나
- 영어 학습 포인트가 묻히거나
- 미니앱의 간결함이 손상되면

해당 요소는 사용하지 않는다.

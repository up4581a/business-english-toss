## 2. Framework check

- **Target:** Korean professionals who can understand ordinary workplace English but hesitate over wording, commitment, certainty, boundaries, and live responses.
- **Stage boundary:** material risk or problem management → Handle It; otherwise live interaction → Speak Up; otherwise routine asynchronous work → Inbox.
- **Learning goal:** pragmatic competence plus reusable business English, not generic workplace judgment or grammar recall.
- **English payoff:** every scenario must support a concrete distinction, frame, collocation, or reusable pattern.
- **Directness neutrality:** direct, concise, firm, factual, diplomatic, and empathetic responses can each be optimal when they best achieve the stated objective.

## 3. Field key

Each record includes all required fields in a compact form.

- **Classification:** `stage`; `situation_family`; channel / communication mode; internal/external context; speaker → counterpart; power relationship; relationship status; stakes
- **Scenario:** the production premise, including any fact, authority, constraint, or negotiability needed to determine a best response
- **Goal / challenge:** business goal; primary communication challenge
- **Style / functions:** desired response style; language functions
- **Payoff / pattern:** expected English payoff; candidate reusable pattern
- **Production:** recommended question types; target difficulty; two distinct candidate distractor types; optional storyline ID

Production metadata uses only the Editorial Guide’s canonical question types: `Best Response`, `Best Revision`, `Tone Check`, `Choose the Follow-up`, `What's Wrong?`, `Order the Message`, and `Fill the Expression`.

- `prompt_scope` may narrow a canonical type to `first question` or `first response` without creating a new question type.
- `content_unit` may identify `spoken response` or `spoken update` when `Order the Message` is used for live content.

## Stage 1 — Inbox (40)

### IN-001 · Define what “review” requires
- **Classification:** `Inbox`; clarification; Email / async; internal; project coordinator → peer; equal; neutral; routine
- **Scenario:** Atlas 시장 분석 보고서를 맡은 다른 팀이 문서를 “review해 달라”고 보냈다. 오늘 안에 필요한 것이 단순 확인인지, 문구 수정인지, 승인인지에 따라 작업량이 달라지며 요청자는 이를 구분하지 않았다.
- **Goal / challenge:** 필요한 response scope를 확정한다; 막연한 “more details” 요청으로 모호함을 유지하지 않고 가능한 작업 단위를 구분한다.
- **Style / functions:** concise; disambiguate intent, offer explicit categories
- **Payoff / pattern:** `review` 같은 넓은 동사를 actionable categories로 바꾸는 법; `Would you like me to check X, revise Y, or approve Z?`
- **Production:** Choose the Follow-up; Difficulty 1 적합; `pseudo-clarification` + `unnecessary assumption`; storyline `SL-ATLAS-REPORT`

### IN-002 · Confirm an agreed input date
- **Classification:** `Inbox`; deadline confirmation; Email / async; external; account coordinator → client; client-facing; formal; routine
- **Scenario:** Pulse 고객은 분기 account review용 원본 데이터를 월요일 오전까지 보내기로 이미 합의했다. 화요일 분석 세션을 지키려면 그 시간이 실제 cutoff이며 변경 여지는 없다.
- **Goal / challenge:** 합의된 제출 시점을 재확인한다; 이미 확정된 마감을 다시 부탁이나 선택사항처럼 만들지 않는다.
- **Style / functions:** direct + clear; confirm agreement, connect deadline to next step
- **Payoff / pattern:** agreed deadline에는 request hedging보다 confirmation framing이 정확하다는 점; `Please send X by [time] as agreed, so we can Y.`
- **Production:** Best Response; Difficulty 1 적합; `reopens an agreed deadline` + `weakens a hard deadline`; storyline `SL-PULSE-ACCOUNT`

### IN-003 · Commit without artificial uncertainty
- **Classification:** `Inbox`; commitment; Messenger / async; internal; analyst → manager; upward; familiar; routine
- **Scenario:** 상사가 오후 4시까지 업데이트된 표를 보낼 수 있는지 묻는다. 작업은 이미 끝났고 검토만 남아 있어 4시 전달이 확실하다.
- **Goal / challenge:** 명확한 약속을 준다; 불필요한 hedge나 effort-only language로 확실성을 낮추지 않는다.
- **Style / functions:** direct + clear; accept task, state firm commitment
- **Payoff / pattern:** `I’ll`과 `I should be able to`·`I’ll try`의 commitment 차이; `Yes, I’ll send X by [time].`
- **Production:** Tone Check; Difficulty 1 적합; `unnecessary hedging` + `effort-only commitment`; storyline none

### IN-004 · Separate a delivery risk from a confirmed delay
- **Classification:** `Inbox`; expectation management; Email / async; external; project manager → external partner; equal; formal; sensitive
- **Scenario:** 필요한 승인 하나가 아직 나오지 않아 금요일 납품이 하루 밀릴 가능성이 있다. 지연은 확정되지 않았고 목요일 정오에는 영향을 판단할 수 있다.
- **Goal / challenge:** 조기 경고와 다음 확인 시점을 제공한다; 가능성을 확정 사실처럼 말하거나 vague update로 끝내지 않는다.
- **Style / functions:** neutral + factual; communicate uncertainty, set update point
- **Payoff / pattern:** `may` + affected outcome + concrete confirmation time; `X may affect Y. We’ll confirm the impact by [time].`
- **Production:** Best Revision; Difficulty 2 적합; `excessive certainty` + `non-actionable update`; storyline none

### IN-005 · Request a dependency with a usable deadline
- **Classification:** `Inbox`; request; Email / async; internal; project manager → peer; equal; neutral; routine
- **Scenario:** 재무팀의 비용 수치가 있어야 제안서를 마칠 수 있다. 제안서 내부 검토는 수요일 오후라서 수치는 화요일 3시까지 필요하다.
- **Goal / challenge:** 필요한 input과 이유·마감을 한 번에 요청한다; 상대를 압박하지 않으면서도 다음 행동을 모호하게 두지 않는다.
- **Style / functions:** diplomatic + collaborative; request input, explain dependency
- **Payoff / pattern:** request에 business reason과 usable deadline을 결합하는 frame; `Could you send X by [time]? We need it to Y.`
- **Production:** Best Response; Difficulty 2 적합; `missing deadline` + `unnecessarily demanding tone`; storyline none

- **Goal / challenge:** 답을 받을 수 있는 follow-up을 보낸다; 단순한 “just checking in”이나 불필요한 압박 대신 decision과 cutoff를 명시한다.
- **Style / functions:** concise; follow up, request decision
- **Payoff / pattern:** status-check를 decision-oriented follow-up으로 바꾸는 법; `Could you confirm X by [time] so we can Y?`

### IN-008 · Hand off work with ownership intact

- **Payoff / pattern:** handoff에서 action·deadline·escalation route를 구조화하는 법; `Please handle X by Y. If Z comes up, contact A.`

### HI-034 · Escalate a refused replacement through the agreed remedy

### HI-036 · Acknowledge a conduct complaint without validating an unverified claim

### HI-037 · Own the missed date without accepting an inaccurate cause

### HI-040 · Issue a final operational escalation with a consequence
